# 图片、名称展示与公告入口修复

## 修复范围

- 议价列表新增商品封面、商品名称和交易对方名称；同时保留已接受、已拒绝、已关闭的议价历史。
- 订单列表和订单详情直接使用订单接口返回的封面和买卖双方名称，去除订单列表逐条查询商品的额外请求。
- 商品详情接口补齐封面字段，修复预约详情、评价页面的同类缺图问题。
- 首页、商品广场、商品详情、商品编辑、我的商品、收藏、订单、预约和评价统一使用图片组件，无图或加载失败时显示本地文字占位，不再依赖外部占位图服务。
- 聊天列表显示对方名称、商品名称和缩略图，窗口标题显示对方名称；消息直接使用接口提供的昵称和头像，避免逐条请求用户资料。快速切换会话时避免旧请求覆盖当前消息。
- 预约列表、订单管理、商品管理、举报管理、审核日志和公告管理补齐可读的商品或用户名称。订单编号和后台追溯编号仍保留。
- 从商品等页面进入举报时，读取实际对象名称展示，仍按原有 ID 提交；手动填写编号时也会解析对象名称供确认。
- 移除订单详情中写死的“信用分 100”，避免展示虚假信用信息。

## 公告在哪里看

此前仅有管理员公告管理页，普通用户没有查看入口，而且读取接口也要求管理员权限。

现在可通过顶部「平台公告」或首页公告卡片进入 `/notices`，无需登录。支持分页、类型筛选、完整正文、加载失败重试及空状态。新增只读接口 `GET /api/notices` 和 `GET /api/notices/{id}`，管理员原有发布、修改和删除权限保持不变。

## 启用与验证

本次无数据库表结构或视图迁移。部署更新后的前后端，开发环境重启后端并刷新前端即可；Docker 部署需要重新构建前后端镜像。

- 前端：`cd frontend` 后执行 `npm run build`（包含 TypeScript 检查）。
- 后端：`dotnet build backend/CampusTrade/CampusTrade.Backend --no-restore`。
- 公告权限回归：`dotnet run --project tests/DisplayContracts`，覆盖匿名读取、无效筛选、删除后的详情、普通用户不可发布/编辑/删除、管理员可发布。
- 数据库启动后，分别用买家和卖家查看议价、订单和聊天，核对封面与名称；检查已完成议价仍在列表中。
- 用管理员发布公告，再用普通用户和未登录窗口打开 `/notices`，验证筛选、全文、编辑后刷新和删除后刷新。

当前环境 Docker 引擎未启动，真实 Oracle 数据和上传图片的端到端联调尚未执行；构建与不依赖数据库的权限回归不能替代该项验证。
